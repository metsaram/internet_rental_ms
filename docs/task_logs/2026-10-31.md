## Task 2: Fix Production Prisma Client Desync (`useContract` on `Company.update()`)
- **Problem**: In production, `prisma.company.update()` (e.g. updating company settings via `PATCH /api/company`) threw:
  ```
  Invalid `prisma.company.update()` invocation:
  data: {
    ...

  ```
- **Root Cause**:

- **Solution**:
  1. Added `"postinstall": "prisma generate"` to `package.json`.
  2. Updated `"build"` in `package.json` to `"prisma generate && next build && cp -r .next/static .next/standalone/.next/ && cp -r public .next/standalone/"`.
  3. Added `bun run db:generate` in `.zscripts/build.sh` before `bun run build`.
  4. Verified `db.company.update()` locally with `useContract: false` payload against Supabase PostgreSQL — confirmed 100% success.

## Task 5: Daily Invoice Payment Alert Notifications (1-Week Due Soon & Overdue Lifecycle)
- **Problem**: Invoices had basic static threshold notifications. User requested:
  - Alert the user to make payment 1 week before the invoice due date if still not paid.
  - Keep alerting every day until overdue by 1 week or status is VOID or paid.
- **Solution**:
  1. Implemented `getInvoicePaymentAlert(invoice, outstandingAmount, now)` in `src/lib/notifications.ts`:
     - Checks if invoice is VOID or fully paid (`outstanding <= 0`) -> returns `null`.
     - Calculates calendar-day difference (`daysToDue = due - now`).
     - Alert window: between 7 days before due date (`daysToDue <= 7`) and 7 days after due date (`daysToDue >= -7`).
     - Pre-due window (`daysToDue >= 0`): generates `INVOICE_DUE_SOON` daily reminder with accurate countdown ("Invoice due in Xd", "Invoice due tomorrow", "Invoice due today") and outstanding balance.
     - Post-due window (`-7 <= daysToDue < 0`): generates `INVOICE_OVERDUE` urgent daily alert with exact overdue day count ("Invoice 1d overdue: was due yesterday", "Invoice Xd overdue: X days past due").
     - Outside window (`daysToDue < -7` or `daysToDue > 7`): returns `null`.
  2. Enhanced `generateNotifications()` in `src/lib/notifications.ts`:
     - Daily throttling check prevents duplicate alerts on the same day (`createdAt >= startOfToday`).
     - In-place refresh updates existing unread alerts for the invoice from a previous day with the new day's countdown and current timestamp, keeping the inbox clean without duplicate rows.
     - Creates a new notification if the user marked previous alerts as read or dismissed them.
     - Automatically cleans up / dismisses active unread alerts when the invoice is marked VOID, paid, or passes 1 week overdue.
  3. Created verifying test suite `test/invoice-notifications.test.ts` (11 tests covering all boundary conditions, balances, voiding, and overdue limits).

## Task 7: Fix Invoice Edit & Save Prisma Error (`serviceId` Unknown Argument)
- **Problem**: When editing an invoice and saving changes, `PATCH /api/invoices/[id]` threw a Prisma Client runtime error:
  ```
  Invalid `db.invoice.update()` invocation:
  Unknown argument `serviceId`. Did you mean `service`? Available options are marked with ?:
  ? company?: CompanyUpdateOneRequiredWithoutInvoicesNestedInput
  ? service?: InternetServiceUpdateOneWithoutInvoicesNestedInput
  ? createdBy?: UserUpdateOneRequiredWithoutInvoicesNestedInput
  ? allocations?: PaymentAllocationUpdateManyWithoutInvoiceNestedInput
  ```
- **Root Cause**:
  - In `src/app/api/invoices/[id]/route.ts`, the update payload object was declared as `const data: Prisma.InvoiceUpdateInput = {}`.
  - In Prisma's relation-based `InvoiceUpdateInput`, scalar foreign keys like `serviceId` do not exist; instead, relations are modified via nested input `service: { connect: { id } }` or `service: { disconnect: true }`.
  - The previous code bypassed TypeScript with `(data as any).serviceId = ...` and mixed it with `data.contract = { disconnect: true }`. At runtime, Prisma's input validator rejected `serviceId`.
- **Solution**:
  1. Updated `src/app/api/invoices/[id]/route.ts`:
     - Replaced all raw scalar assignments `(data as any).serviceId = ...` with Prisma relation nested inputs:
       - If contract connected with a linked service: `data.service = contract.serviceId ? { connect: { id: contract.serviceId } } : { disconnect: true }`
       - If contract disconnected and direct `serviceId` specified: `data.service = { connect: { id: body.serviceId } }`
       - If `serviceId` is null/omitted: `data.service = { disconnect: true }`
     - Removed all `(data as any)` typecasts so `data` is 100% type-safe under `Prisma.InvoiceUpdateInput`.
  2. Created unit test suite `test/invoice-update.test.ts` verifying:
     - Updating an invoice with direct service and disconnected contract properly generates `{ contract: { disconnect: true }, service: { connect: { id } } }` without scalar `serviceId`.
     - Updating an invoice with a contract properly connects both contract and its linked service.
     - Disconnecting both contract and service properly generates `{ disconnect: true }` for both relations.
  3. Verified all Vitest tests pass (`npx vitest run test/invoice-update.test.ts` -> 3/3 passed; full test suite -> 24 test files, 218 tests passing).
