# Task Log: 2026-10-31

## Task 1: Fix Dashboard Load Data Error (Unknown field `useContract` on `Company`)
- **Problem**: When loading the dashboard (`/api/dashboard`), the API returned:
  ```
  Invalid `prisma.company.findUnique()` invocation:
  select: {
    useContract: true,
    currency: true
  }
  Unknown field `useContract` for select statement on model `Company`. Available options are marked with ?.
  ```
- **Root Cause**:
  - The `useContract Boolean @default(true)` field was added to the `Company` model in `prisma/schema.prisma` and applied to PostgreSQL, but `prisma generate` had not been executed to regenerate the Prisma Client types and query engine metadata for the application runtime.
- **Solution**:
  1. Ran `bun run db:generate` (`prisma generate`), successfully generating the updated `@prisma/client` (v6.19.2) with `useContract` on `Company`.
  2. Verified `db.company.findUnique({ where: { id: cid }, select: { useContract: true, currency: true } })` succeeds directly via `src/lib/db`.
  3. Verified all 12 concurrent queries in `src/app/api/dashboard/route.ts` against the database.
  4. Tested the live endpoint `http://localhost:3000/api/dashboard` with authenticated session — confirmed HTTP 200 response with full dashboard metrics, counts, spend aggregations, renewals, and activity.
  5. Ran full Vitest test suite (`bun run test:run`) — 21 test files and 198 tests passing.


## Task 2: Fix Production Prisma Client Desync (`useContract` on `Company.update()`)
- **Problem**: In production, `prisma.company.update()` (e.g. updating company settings via `PATCH /api/company`) threw:
  ```
  Invalid `prisma.company.update()` invocation:
  data: {
    ...
    useContract: false,
    ~~~~~~~~~~~
  }
  Unknown field `useContract` for update statement on model `Company`.
  ```
- **Root Cause**:
  1. `package.json` had neither `"postinstall": "prisma generate"` nor `"prisma generate"` in `"build"`.
  2. In Next.js standalone mode (`.next/standalone`), Next traces and copies `node_modules/@prisma/client` and `.prisma/client` at build time. Because `prisma generate` was not executed in the production build pipeline, the production runtime and standalone bundle (`.next/standalone/server.js`) ran with a stale Prisma client generated before `useContract` was added.
- **Solution**:
  1. Added `"postinstall": "prisma generate"` to `package.json`.
  2. Updated `"build"` in `package.json` to `"prisma generate && next build && cp -r .next/static .next/standalone/.next/ && cp -r public .next/standalone/"`.
  3. Added `bun run db:generate` in `.zscripts/build.sh` before `bun run build`.
  4. Verified `db.company.update()` locally with `useContract: false` payload against Supabase PostgreSQL — confirmed 100% success.
  5. Provided exact production remediation commands (`bun run db:generate && bun run build && restart server`).
