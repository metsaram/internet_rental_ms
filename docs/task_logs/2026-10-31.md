## Task 7: Fix Invoice Edit & Save Prisma Error (`serviceId` Unknown Argument)
- **Problem**: When editing an invoice and saving changes, `PATCH /api/invoices/[id]` threw a Prisma Client runtime error:
  ```
  Invalid `db.invoice.update()` invocation:
  Unknown argument `serviceId`. Did you mean `service`? Available options are marked with ?:
  ? company?: CompanyUpdateOneRequiredWithoutInvoicesNestedInput
  ? service?: InternetServiceUpdateOneWithoutInvoicesNestedInput
  ? createdBy?: UserUpdateOneRequiredWithoutInvoicesNestedInput
  ? allocations?: PaymentAllocationUpdateManyWithoutInvoiceNestedInput
  ```
- **Root Cause**:
  - In `src/app/api/invoices/[id]/route.ts`, the update payload object was declared as `const data: Prisma.InvoiceUpdateInput = {}`.
  - In Prisma's relation-based `InvoiceUpdateInput`, scalar foreign keys like `serviceId` do not exist; instead, relations are modified via nested input `service: { connect: { id } }` or `service: { disconnect: true }`.
  - The previous code bypassed TypeScript with `(data as any).serviceId = ...` and mixed it with `data.contract = { disconnect: true }`. At runtime, Prisma's input validator rejected `serviceId`.
- **Solution**:
  1. Updated `src/app/api/invoices/[id]/route.ts`:
     - Replaced all raw scalar assignments `(data as any).serviceId = ...` with Prisma relation nested inputs:
       - If contract connected with a linked service: `data.service = contract.serviceId ? { connect: { id: contract.serviceId } } : { disconnect: true }`
       - If contract disconnected and direct `serviceId` specified: `data.service = { connect: { id: body.serviceId } }`
       - If `serviceId` is null/omitted: `data.service = { disconnect: true }`
     - Removed all `(data as any)` typecasts so `data` is 100% type-safe under `Prisma.InvoiceUpdateInput`.
  2. Created unit test suite `test/invoice-update.test.ts` verifying:
     - Updating an invoice with direct service and disconnected contract properly generates `{ contract: { disconnect: true }, service: { connect: { id } } }` without scalar `serviceId`.
     - Updating an invoice with a contract properly connects both contract and its linked service.
     - Disconnecting both contract and service properly generates `{ disconnect: true }` for both relations.
  3. Verified all Vitest tests pass (`npx vitest run test/invoice-update.test.ts` -> 3/3 passed; full test suite -> 24 test files, 218 tests passing).
